# 스마텍 홈페이지 SEO·GEO 검토 — 2026-09-09

현재 검색 접근의 기본 구조는 갖춰져 있다. 먼저 개선할 것은 **기존 기술 글의 정확성·근거 연결, 모바일 홈페이지 속도, 실제 내용과 검색용 정보의 일치**다. 새 글은 월·목 2편으로 운영하면서 기존 글을 영향 순으로 교정하는 방향이 적절하다. 모델 변경·발행 편수·문장 일부 수정만으로 검색 성과를 보장할 수는 없다.

## 조사 범위와 증거

- 로컬 코드와 루트 규칙, 블로그 규칙·작성/리서치/이미지/통합 가이드, 과거 Claude 메모리의 관련 이력을 대조했다.
- 실제 공개 사이트맵 1,162개 URL, 중복 URL 0개. 블로그 54개, 제품·모델 경로 1,081개, 주요 페이지·산업 페이지 27개.
- **102개 공개 페이지 HTTP 점검**: 블로그 54개 전체 + 주요·산업 27개 + 제품 표본 18개 + 정책 페이지 3개. 모두 HTTP 200. 제품 1,081개 전체를 크롤링한 결과는 아니다.

- Google PageSpeed API는 429 할당량 오류로 측정하지 못해 로컬 설치 도구를 사용했다. Lighthouse 종료 시 Windows 임시 폴더 정리 EPERM이 있었으나 보고서 생성·categories·metrics·`runtimeError` 없음까지 확인했다. 이 종료 오류를 보고서 오류와 혼동하지 않는다.

- **GEO 종합 점수는 만들지 않았다.** AI 인용·유입·문의 자료 없이 자체 숫자를 공인 점수처럼 제시하지 않는다.

- 공개 대표 주소가 `https://www.smartechvacuum.com`으로 일관된다. 점검 표본 102개 canonical은 각 URL과 일치했고 title 중복은 없었다.

- 블로그 Article·작성자 Robin·작성자 소개 URL·발행/수정 시각, 산업별 페이지, 제품/모델 상세 경로, 관련 글과 문의 연결이 이미 있다. 새로 없는 기능처럼 다시 만들 필요가 없다.

## 개선 우선순위

### 1. 기술 정확성과 출처 연결 — 가장 먼저

- 공개 블로그 54개 모두 `<article>` 안의 클릭 가능한 링크가 0개였다. 페이지 바깥 관련 글·문의 버튼까지 없는 것은 아니다.
- 기존 파서에는 Markdown 링크 처리가 없어 글에 출처를 넣어도 클릭 가능한 링크로 표시되지 않았다.
- 로컬 작성 규칙이 공식 출처 표시를 금지하고 일부 조건부 표현을 단정으로 바꾸게 되어 있었다. 출처·모델 조건·검증 이력을 보존하도록 수정했다.
- 공개 기존 글에서 EH 부스터 대기압 시작, EMF 미스트필터 매칭 등 우선 확인할 문제를 발견했다. 글별 문구·URL·근거·수정 범위는 블로그 보고서에 있다. 기존 공개 글의 DB 본문은 이번에 일괄 덮어쓰지 않았다.
- 개선 기준: 질문에 대한 답 → 적용 모델·조건 → 확인 가능한 근거 → 실제 점검 항목 → 관련 제품/상담으로 연결한다. 경력·고객 사례·시험 수치는 확인된 것만 사용한다.
- 단어를 몇 개 바꾸거나 날짜만 갱신하는 일보다 독자에게 추가 판단 근거를 주는 변경이 우선이다. Google도 실제 경험·독창적 설명·신뢰할 수 있는 근거를 강조하며, 선호하는 글자수 기준을 제시하지 않는다. [유용하고 신뢰할 수 있는 콘텐츠 안내](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)

### 2. 홈페이지 모바일 표시 속도 — 기술 개선 1순위

- 모바일 성능 55, LCP 11.2초. 다운로드 총량 약 4,138KiB, 이미지 개선 예상 절감량 약 1,312KiB, 미사용 JavaScript 예상 절감량 약 96KiB로 보고됐다. 예상치는 합산 성능 보증값이 아니다.
- LCP 요소로 홈페이지 도입 설명 `<p class="... hero-rise">`가 기록됐다. `app/page.tsx`·`app/globals.css`의 초반 표시/애니메이션과 초기 자바스크립트 실행을 함께 추적할 필요가 있다. 동영상 하나가 원인이라고 단정하지 않는다.
- hardware.png, next.png, gauges-indirect.png 등이 표시 크기보다 크다. 디자인 토큰을 바꾸지 않고 이미지 전달 크기·형식·로딩 순서부터 별도 검증할 수 있다.
- 점검 표본의 img 492개에는 HTML width/height 속성이 없었다. CSS로 크기를 잡은 요소도 있으므로 “492개 모두 레이아웃 이동 발생”이라는 뜻은 아니다. 블로그 이미지부터 실제 크기와 공간 예약을 확인한다.
- 다음 구현 단위: 홈 첫 화면과 이미지 요청을 먼저 측정 → 필요한 크기만 전달 → 동일 모바일 조건 재측정. `globals.css` 등 보호 파일 수정이 필요하면 해당 변경안을 별도로 승인받는다.
- 로그인·등급 가격·고객 데이터가 있는 경로를 성능 때문에 무조건 캐시하지 않는다. 과거 캐시 회귀 메모리를 먼저 확인한다.

[구조화 데이터 일반 지침](https://developers.google.com/search/docs/appearance/structured-data/sd-policies), [Product 안내](https://developers.google.com/search/docs/appearance/structured-data/product-snippet)

### 4. 페이지 내용·발견 경로

- 공개 블로그 52/54개에서 헤더 제목과 본문 제목이 중복 H1으로 표시됐다. 순위 벌점으로 단정할 문제는 아니지만 읽기 구조를 정리할 수 있다. 공통 렌더러에서 중복 제목과 내부 편집 주석을 제거하도록 보완했다.
- `/products`는 초기 HTTP HTML에 H1이 없었다. `useSearchParams`를 쓰는 클라이언트 내용을 fallback 없는 Suspense로 감싸고 있어, 공개 소개·카테고리 링크를 서버 영역에서 제공하는 개선을 검토한다. 브라우저 렌더링 후에도 제목이 없다는 뜻은 아니다.
- `/blog/battery-manufacturing-dry-pump-pfpe-oil` 1개에 description이 없었다. DB 원고 교정 시 내용을 확인해 적절한 요약을 채운다.
- 제품 표본은 HTTP 응답·제목·canonical은 정상이나 설명이 품명·품번·가격 중심인 경우가 있다. 모든 SKU 설명을 기계적으로 늘리기보다 핵심 모델 페이지에 선정 조건·호환 범위·공식 카탈로그 근거를 연결한다.
- `/api/` robots 차단으로 `/api/photos?serve=...` 형태의 공개 현장사진과 카탈로그 API도 검색봇 접근이 제한된다. API 전체 차단을 해제하지 말고 공개 자산만 별도 안정된 경로로 제공할 필요가 있는지 확인한다.
- `robots.txt`의 `/admin/` 같은 경로 차단은 인증·noindex를 대신하지 않는다. 이번에 인증 동작이나 비공개 페이지를 종합 보안 감사한 것은 아니다.

### 5. GEO와 실제 마케팅 성과

- Google은 AI 검색에도 기존 SEO 원칙을 적용하며 llms.txt·특수 AI 파일이 Google 검색 노출이나 순위에 영향을 주지 않는다고 명시한다. 현재 llms 파일을 늘리는 작업보다 유용한 본문·근거·제품/회사 정보의 일치에 시간을 쓴다. 다른 AI 서비스에 같은 결론을 자동 적용하지 않는다. [Google AI 검색 최적화 안내](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)
- 일반 진공이론 글과 산업별 실제 의사결정 글을 섞는다. 산업명만 교체한 유사 글을 늘리지 않는다.
- Google Business Profile·네이버 업체 정보의 회사명·전화·주소·영업시간, 공식 파트너 근거를 실제 프로필과 대조하는 것이 후속 업무다. 과거 등록 완료 메모리가 현재 상태 확인을 대신하지 않는다.
- Search Console 최신 28일/이전 28일: 노출·클릭·질의·페이지별 CTR·색인 문제를 확인한다. GA4: 검색/AI 추천 유입과 실제 문의 완료·전화 클릭을 분리한다. 기존 GA4 태그는 있으나 이번에 계정의 최신 실적을 읽지는 않았다.
- 대표 질문 10~15개를 고정해 AI 답변에서 스마텍 언급·실제 인용 URL·잘못된 제품 설명을 같은 조건으로 기록할 수 있다. 한 번의 AI 답변이나 referral 유입만으로 GEO 효과의 원인을 입증하지 않는다.
