SECTION 03

AI 자동화를 위해 반드시 강화할 4가지

1 데이터 구조화

지금 수리 이력은 텍스트로만 저장돼 있어요. AI가 패턴을 찾으려면 증상·원인·부품교체 항목을 코드로 분류해야 해요. 예: "오일 오염 → code: OIL_CONTAMINATION"처럼 정해진 항목으로. 이 작업은 지금 당장 시작할 수 있고, 100건만 쌓여도 AI 분석이 가능해져요.

2 시리얼번호 기반 펌프 이력 DB

지금은 "A회사 펌프 수리"만 알아요. 앞으로는 "A회사의 GXS450 S/N 123456의 전체 수리 이력"을 조회할 수 있어야 해요. 시리얼번호가 펌프의 주민등록번호 역할. 이걸 기반으로 예측 정비와 고객 포털이 만들어져요.

3 공정 정보 수집

같은 GXS450이라도 반도체 CVD 공정에서 쓰면 18개월마다, 일반 연구용으로 쓰면 36개월마다 오버홀이 필요해요. 견적 문의·수리 접수 시 "어떤 공정에 사용하시나요?" 항목 하나를 추가하면 AI 예측 정확도가 3배 이상 올라가요.

4 자동화 스케줄러 인프라

예방정비 문자, 후속 이메일, 견적 만료 알림 등 "미래 시점에 자동으로 실행되는 작업"을 처리하는 엔진이 필요해요. 지금은 이 인프라가 없어요. Vercel Cron Jobs 또는 외부 스케줄러를 준비하면 모든 자동화 기능의 기반이 돼요.

  • ✅ 시리얼번호 기반 펌프 개체 이력 DB 구축

SECTION 06

작업 충돌 방지 — 파일 소유권 지도

⚠️ 동시에 건드리면 충돌 위험이 있는 파일들

app/api/chat/route.ts AI 챗봇 스트리밍 + 시뮬레이션 KB 로딩 담당. 예방정비 챗봇 연동 작업 시 시뮬레이션 KB 작업과 동시 수정 금지.
prisma/schema.prisma DB 구조 파일. 시리얼번호·점검일 필드 추가 시 반드시 단독 작업. 변경 후 npx prisma db push 필수.
lib/pumpSpeedData.ts 펌프 속도 커브 데이터. 시뮬레이션 업데이트 작업 전용. 챗봇·UI 작업과 분리.
data/simulation-cases/ 시뮬레이션 KB 케이스 파일. 추가만 가능. 기존 파일 삭제·수정 금지.
권장 작업 순서 (Phase 1 기준)
1 DB 스키마 확정 — serialNumber·predictedServiceDate·symptomCategory 필드 추가 (schema.prisma 단독 작업)
2 수리 접수 UI 업데이트 — 시리얼번호·공정 유형·점검일 입력 필드 추가
3 SMS 자동 발송 로직 — 납품 완료 이벤트 → 즉시 문자 (Solapi 기존 연동 활용)
4 스케줄러 구축 — Vercel Cron → 매일 점검 예정일 D-30 체크 → 리마인더 문자
5 고객 포털 — 로그인 후 내 펌프 이력·다음 점검일 확인 페이지
SECTION 07

스마텍만 할 수 있는 이유

🏆 실제 수리 데이터 독점 보유

Edwards 공식 대리점으로 쌓인 수년치 수리 이력. 경쟁사는 이 데이터를 구조적으로 가질 수 없어요. 이 데이터가 AI 예측 모델의 핵심 재료가 돼요.

⚡ 실측 펌프 커브 데이터

GXS·nXRi·iH 시리즈 전체의 PumpCalc 기반 실측 속도 커브. 시뮬레이션 정확도 ±1.1% 이내. 홈페이지에 공개 구현된 사례는 한국에서 스마텍이 유일해요.

🔗 고객사 직접 연결 채널

거래처 담당자 DB + SMS 직접 발송 채널 보유. 고객과의 관계를 플랫폼이 가져가지 않고 스마텍이 직접 유지해요. 이 채널 위에 모든 자동화 서비스가 올라가요.

🧠 AI 상담 + 기술 지식의 결합

챗봇이 시뮬레이션 KB·스펙 데이터·수리 사례를 동시에 참조해요. "이 조건에 몇 대 필요해요?"부터 "언제 오버홀해야 해요?"까지 한 채널에서 답해요.
