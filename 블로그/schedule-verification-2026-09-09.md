# 월·목 발행 전환 검증 — 2026-09-09

사용자 승인에 따라 2026-09-14부터 `day1=월요일`, `day2=목요일` 주 2편으로 전환하는 코드를 준비했다. 이번 금요일 `0911-아웃가스-원리`는 사용자 업로드 요청을 기다린다.

## 변경 내용

- `auto_upload.py`: 큐 `_week`의 ISO 주차와 슬롯으로 정확한 날짜를 계산한다. 같은 요일이어도 다른 주차이면 업로드하지 않는다. 전환 전 큐에는 기존 월·수·금 규칙을 적용하고, 전환 후 큐는 월·목만 허용한다.
- 승인 값은 JSON `true`, 미발행 값은 JSON `false`인 경우에만 진행한다. `--force`로 날짜를 우회하는 기능은 차단한다.
- `--dry-run`은 네트워크 요청 없이 일정·승인 조건을 검사한다. 날짜가 맞지 않으면 건너뛴 이유를 로그에 남긴다. 실제 원고 품질 검사는 기존 `upload_post.py`가 발행 전에 수행한다.
- 업로드 도중 큐가 바뀌면 오래된 내용으로 덮어쓰지 않는다. 정상 완료 상태는 임시 파일을 거쳐 교체한다.
- `setup_scheduler.ps1`: 기존 작업 정의를 XML로 백업한 다음 월·목 09:00 작업을 등록하고 수·금 및 임시 화·목 작업을 삭제 대신 비활성화한다. 시작일은 9/14와 9/17이다.
- `Hidden` 설정과 `pythonw.exe`, 자식 프로세스 `CREATE_NO_WINDOW`로 콘솔 클릭 정지 문제를 방지한다. Windows가 한국 시간대인지 먼저 확인한다.

## 적용 및 운영 주의점

### 실제 적용 시도 결과 — 메인 담당자

- 실제 Windows `-WhatIf` 확인 성공: 기존 월·수·금 3개 작업 대상.
- 실제 실행은 XML 백업 3개를 만든 뒤 첫 월요일 작업 등록에서 `Access is denied (0x80070005)`로 중단됐다.
- 도구 권한을 높여 재시도한 상태에서도 Windows 관리자 권한이 필요했다. 자동 승인 검토 거절이 아닌 OS 권한 오류다.
- 재조회에서 기존 월·수·금 작업과 실행 경로·시작일이 유지됐고, 목요일 새 작업은 없음을 확인했다.
- 따라서 아래 계획은 **코드·모의 검증 완료, Windows 실제 적용 미완료**다. 관리자 PowerShell에서 실행 후 다시 조회해야 한다.
- 다음주 수요일 기존 작업은 새 Python 날짜 검사에서 건너뛴다. 목요일 새 작업이 없으므로 실제 등록 전에는 목요일 자동 발행을 약속하지 않는다.

실제 작업 등록은 메인 담당자가 아래 미리보기 확인 후 별도로 적용·조회한다. XML 백업은 `블로그/scheduler-backups/실행시각/`에 생성되며 실제 처리 내역은 `upload-log.txt`에 기록된다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File './블로그/setup_scheduler.ps1' -WhatIf
powershell -NoProfile -ExecutionPolicy Bypass -File './블로그/setup_scheduler.ps1'
```

- 기존 W37 `upload-queue.json`을 보존했다. 검증 시 day1·day2만 있었으며, 금요일 아웃가스 원고는 아직 day3에 등록되지 않았다.
- 금요일 자동 작업은 비활성화하는 계획이다. 금요일에 사용자 요청과 원고·사진 승인을 확인한 뒤 해당 글 하나만 수동 업로드한다.
- 다음주 원고 2편을 선택·작성·검수하고 예약 승인을 받아야 W38 큐를 채울 수 있다. 현재 큐를 다음주 자료로 미리 덮어쓰지 않는다.
- `approve_post.py`는 사전예약 승인 전용 도구가 아니다. 실행하면 승인과 동시에 업로드한다. 사전예약 용도로 실행하면 안 된다.
- 이번 변경은 자동 업로드 경로를 보호한다. `approve_post.py`와 `upload_post.py` 직접 실행의 기존 정책은 변경하지 않았으므로, 수동 실행 전 날짜·이미 발행 여부를 담당자가 확인해야 한다.
- 예약 시각에 PC가 꺼져 있다가 같은 날 켜지면 실행할 수 있지만, 날짜를 넘겼으면 자동 발행을 건너뛴다. 누락분은 사용자의 새 일정 승인을 받아 처리한다.
