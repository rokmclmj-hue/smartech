사용자가 선택하고 작성 승인한 주제에 대해 웹 리서치를 수행하고 결과를 저장한다. 후보 검토 요청만으로 원고 폴더를 만들거나 작성·예약을 시작하지 않는다.

---

## 🔴 핵심 원칙 — Retrieve First, Source Attribution, Refusal-as-Default

1. **Retrieve First**: AI가 알고 있는 내용으로 쓰지 않는다. 반드시 아래 허용 소스에서 찾아서 쓴다.
2. **Source Attribution**: 수치뿐 아니라 제품 기능·운전 절차·가스 적합성·안전 주장에도 실제 읽은 원문 URL과 문서명·버전·페이지(해당 시)를 붙인다. ✅는 읽고 조건까지 검증한 항목에만 붙인다.
3. **Refusal-as-Default**: 허용 소스에서 확인할 수 없는 수치는 절대 쓰지 않는다. "확인 불가"로 표시한다.

## 작동 방식

### 0단계 (현장사례 모드 전용) — 업체 리서치

> **현장사례 모드일 때만 실행한다.** 일반 기술 블로그 글에는 해당 없음.

`info.txt`에서 업체명과 공정 정보를 읽고 아래를 수행한다.

1. **업체 홈페이지 검색**: `업체명 site:업체도메인` 또는 `업체명 공식 홈페이지`
   - 주요 사업 분야, 생산 공정, 사용 장비 파악
2. **공정 일반화**: 업체 특정 없이 동종업계 공정 검색
   - 예: "촉매 분석 연구소 진공펌프 공정" / "촉매 제조 진공 시스템"
3. **제품 적합성 근거**: 납품된 제품(T-Station 85D 등)이 해당 공정에 적합한 이유 정리
4. **research.md 저장 시**: 공개될 수 있는 산출물에는 업체 실명·이니셜을 옮기지 않고 공정·증상 중심으로 익명화한다. 원본 상담·info.txt에서 확인한 사실과 일반 조사 결과를 분리한다.

---

### 0단계 — 스마텍 내부 자료 우선 확인
아래 파일을 먼저 읽는다. 주제와 관련된 제품·조합·현장 사례를 글에 반영한다.

**① 제품 조합 지식 파일 확인 (펌프+부스터 관련 글이면 필수)**
`블로그/knowledge/product_combos.txt` 를 먼저 읽는다.
- GXS 콤비타입(GXS250/2600 등)과 GXS 단독+EH 별도 구성의 차이를 확인한다.
- 스마텍 현장 확인 조합표(GXS160+EH1200, GXS250+EH2600, GXS450+EH4200 등)를 기준으로 사용한다.
- 이 파일에 없는 조합은 "현장 확인 필요"로 표시한다.

**② product_master_table 확인**
`C:\Users\rokmc\smartech\data\Product_master_table\` 폴더에서 주제 관련 제품 파일을 읽는다.
배기속도·도달진공도·권장 조합과 원본 출처를 확인한다. 내부 표와 제조사 문서가 충돌하면 모델·버전·주파수·측정 조건을 대조하고 충돌을 기록한다. 해소되지 않은 핵심 사항은 사용자 확인 전까지 단정하지 않는다.

**③ 상담기록 참조**
`C:\Users\rokmc\smartech\data\상담기록\` 폴더에서 주제 관련 파일을 최대 5개 읽는다.
고객이 실제로 쓴 표현, 반복된 증상, 실제 현장 조합을 추출한다.
발견한 내용은 research.md의 **"현장 사례"** 섹션에 별도 정리한다.

### 1단계 — 허용 소스 우선 검색
WebSearch 시 반드시 허용 소스 도메인을 지정하거나, 검색 결과 중 허용 소스만 선택한다.
검색 예시: `site:edwardsvacuum.com GXS EH booster combination`

핵심 주장과 적용 조건을 뒷받침할 공식 자료를 확보한다. 자료 개수를 채우려고 무관한 링크를 추가하지 않는다.
허용 소스에서 충분한 정보를 못 찾으면 검색어를 바꾸어 재시도한다.
5회 재시도 후에도 허용 소스에서 찾지 못한 수치는 research.md에 "확인 불가"로 표시한다.

### 2단계 — 제품 조합 규칙 (펌프+부스터 관련 글에 필수 적용)

글 주제가 펌프+부스터 조합(드라이펌프+루츠, 로터리+루츠, 드라이+이젝터 등)을 다룰 때:

1. Edwards 공식 데이터시트 또는 product_master_table에서 해당 펌프의 **권장 조합 모델**을 먼저 확인한다.
2. 공식 문서에 명시된 조합만 "권장 조합"으로 기술한다.
3. 일반 배수 규칙을 모델 추천에 적용하지 않는다. 원리를 설명할 때에도 적용 조건과 근거가 확인되지 않은 “2~8배” 같은 수치를 넣지 않는다.
4. 상담기록에 실제 사용 조합이 있으면 그것을 "현장 사례"로 별도 기술한다.
5. 이 규칙은 GXS+EH뿐 아니라 모든 펌프+부스터 조합에 동일하게 적용된다.
   예: EXS+EH, RV+루츠부스터, nXDS+루츠, iXH+EH 등

### 3단계 — 정보 정리
- 섹션 구분은 주제 특성에 맞게 자유롭게 결정한다.
- 단순 키워드 나열이 아닌, 실제 내용이 담긴 문장으로 정리한다.
- 수치는 반드시 인라인 출처와 함께 기록한다.
  - 형식 예: [모델] 배기속도 [확인한 값과 단위] ([주파수·조건]) ✅ [해당 제조사 데이터시트](실제 URL), p.[페이지]
  - 금지 예: EH2600 배기속도 약 2600 m³/h
- 모델·가스·주파수·압력·온도·작동 모드와 필수 예외를 함께 정리한다. 조건부 사실을 모든 모델의 규칙으로 바꾸지 않는다.
- 안전·유지보수 안내는 해당 제조사의 절차와 범위로 제한한다. 오일프리=정비 불필요, 드라이=모든 가스에 안전처럼 추론하지 않는다.
- 정보가 충돌하면 양쪽 모두 기록하고 충돌한다고 명시한다. 실제 사례·계산 예시·제조사 권장을 구분한다.
- 확인 불가 수치는 임의로 채우지 않는다.

### 4단계 — 저장
`블로그/output/[주제]/research.md` 경로에 저장한다.
승인받은 주제의 폴더가 없으면 생성한다. 기존 파일이 있으면 현재 내용과 변경 이력을 확인해 필요한 부분을 보완하며 사용자 수정 내용을 덮어쓰지 않는다.

### 5단계 — 상담기록 사용 후보를 메인 담당자에게 전달

- 참고한 상담기록과 원고에 실제 사용할 사실을 분리해 전달한다. 리서치 담당자가 공유 `topic-tracker.json`을 직접 수정하지 않는다.
- 원고 작성·검수 완료 후 메인 담당자가 실제 사용한 기록만 `used_consultation_records`에 추가한다. 읽기만 한 자료·후보 검토 자료는 소모하지 않는다.
- `completed_topics`는 작성완료 이력이며 홈페이지 발행 여부를 뜻하지 않는다. 후보 검토나 리서치 완료만으로 추가하지 않는다.

## 지킬 것

- 출처 없는 수치·빈도·경력·현장 결과는 적지 않는다.
- 공개 원고에도 근거 링크가 이어지도록 핵심 주장별 공식 링크와 요약을 제공한다.
- 허용 소스 외 수치는 사용하지 않는다.
- 펌프+부스터 조합은 공식 문서 또는 상담기록 기반으로만 기술한다.
- 추측·창작 금지. 검색으로 확인한 것만 기록한다.
- 글쓰기 에이전트가 바로 활용할 수 있을 정도로 내용을 충실하게 정리한다.
