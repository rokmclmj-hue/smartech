## 검수 항목 (check_quality.py가 자동 판정)

| # | 항목 | 통과 기준 | 실패 시 조치 |
|---|------|----------|------------|
| 1 | 글자수 | final.md 마크다운 제거 후 2,000자 이상 | 필요한 설명을 보완, 허구·반복으로 채우기 금지 |

| 9 | 네이버글 | 1,500자 이상·이미지 마커·해시태그·서명 | naver.md의 실제 부족 항목 수정 |

### 자동 검사의 범위와 예외 확인

- 검사 통과·실패·건너뜀을 구분한다. 현재 EXIF 검사는 field-* 파일에 한정되므로 최종 사진N.png의 방향·손상 여부를 별도로 직접 확인한다.
- 현장사진 조건은 blur-config.json 또는 no-field-photo.md 존재로 통과할 수 있다. 파일 존재만으로 실제 처리나 사진 적합성이 확인된 것은 아니다.
- 현장사진이 없으면 image-maker의 소스 우선순위를 거친 대체 사유를 기록한다. 확인하지 않은 사유나 사용하지 않은 블러 설정을 만들어 검사를 통과시키지 않는다.
- 사례 사진의 블러 필요 여부는 info.txt와 실제 기밀 노출을 확인한다. 블러 불필요여도 EXIF 방향·크기·용량·기밀 여부 점검은 필요하다.
- 분량만 부족하다고 사례·빈도·숫자·중복 결말을 추가하지 않는다. 실질 보완이 필요 없는 길이 미달은 담당자에게 보고하고 기준 검토 전까지 발행을 보류한다.

## 처리 순서

### 전체 통과 시

```
✅ check_quality.py 전체 통과
원문·사진·실제 파일 확인 결과:
   - 핵심 기술 주장과 공식 링크의 모델·가스·운전 조건이 일치하는가?
   - 펌프 본체가 선명한가?
   - 블러가 필요한 배경과 고객사 식별 정보가 보호됐는가?
   - 사진 속 실제 모델·타입과 캡션이 일치하는가?
   - naver.md·google.md·final.md·FAQ에 같은 사실과 조건이 유지됐는가?

검수 완료. 해당 원고·사진 및 발행 날짜에 대한 사용자 승인 대기.
```

- 사용자 선택 전 새 원고를 만들지 않는다. 2026-09-14부터 후보 5개 중 사용자 2개 선택, 월·목 주 2편이다.
- 검수 담당자가 임의로 approved·uploaded를 변경하지 않는다. `completed_topics`는 작성완료 이력이며 홈페이지 공개 여부와 구분한다.
- 예약 승인은 지정 날짜의 자동 발행 허용, 즉시발행은 지금 한 편을 올리라는 요청이다. `approve_post.py`는 즉시 업로드하므로 미래 예약 승인에 실행하지 않는다.
- `0911-아웃가스-원리`는 9/11 사용자의 별도 업로드 요청을 기다린다.

### 실패 항목 있을 시

실패 항목별로 아래 에이전트를 재실행한다.

| 실패 항목 | 재실행 에이전트 |
|----------|--------------|
| 글자수 미달 | `agents/writer.md` (final 2,000자·naver 1,500자 내부 기준, 무의미한 채우기 금지) |
| 메타설명 없음 | `agents/writer.md` (meta.txt description 항목 추가) |
| 현장사진 없음 / EXIF 오류 | `blur_photo.py` 실행 |
| 펌프좌표 오류 | `blur-config.json` 수정 후 `blur_photo.py` 재실행 |

재작업 완료 후 check_quality.py를 다시 실행해 전체 통과를 확인한다.

## 주의

- check_quality.py는 upload_post.py 내부에서도 자동 실행됨 (이중 차단).
- 검수 담당자의 시각 확인과 사용자의 사진 승인은 모두 필요하다. 한쪽으로 다른 쪽을 대신하지 않는다.
- 원고·검증 로그·공개 상태를 확인하지 않고 완료라고 보고하지 않는다. 이번 검수 결과와 남은 승인 사항을 메인 담당자에게 전달해 작업 로그에 기록한다.
- 결과는 `블로그/quality-log.jsonl`에 항목별로 기록됨 (나중에 임계값 조정 시 참고).
