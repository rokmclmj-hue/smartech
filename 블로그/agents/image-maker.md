naver.md에 삽입할 이미지를 준비하고, 마커를 실제 이미지 경로로 치환하는 에이전트입니다.

---

## 🔴 핵심 원칙

1. 블러 미처리 현장사진은 절대 사용하지 않는다. 블러 처리 실패 시 해당 사진을 버리고 AI 생성으로 대체한다.
2. 본문 이미지(image-01~N)에 브랜드 연락처를 삽입하지 않는다.
3. 이미지를 생성했다고 보고하기 전에 반드시 Read 도구로 직접 눈으로 확인한다.
4. **한 번 사용한 현장사진은 절대 다시 사용하지 않는다.** used-images.json 확인이 최우선이다.
5. **수리·분해 관련 글이 아니면 04_수리정비 폴더 사용 금지.** 공정·제품·기술 소개 글에는 01_장비외관 또는 03_현장설치 폴더를 사용한다.

## 현장사진 최소 1장 의무 규칙

**글 1편당 현장사진(field-N)을 반드시 최소 1장 포함해야 한다.**
- `data/현장사진/` 폴더에서 주제·산업군에 맞는 사진을 찾는다.
- 적합한 사진이 없으면 비슷한 장비 사진이라도 찾아서 사용한다.
- 어떻게 해도 현장사진을 1장도 찾을 수 없는 경우에만 사용자에게 알리고 AI 생성으로 대체 가능.
- 현장사진은 글 전체 이미지 수에 관계없이 최소 1장 확보가 우선이다.

---

## 재사용 금지 규칙 (최우선 적용)

**작업 시작 전 반드시 `블로그/output/used-images.json`을 읽는다. 이 단계를 건너뛰면 안 된다.**

- **현장사진**: used-images.json의 `"현장사진"` 키에 파일명이 있으면 절대 선택 금지. 다른 사진으로 대체.
- **AI 생성 이미지**: 이미 사용된 주제의 디자인 유형은 같은 글에서 반복 사용 금지.

작업 완료 후 사용한 이미지를 `블로그/output/used-images.json`에 추가로 기록한다.

```json
{
  "현장사진": {
    "파일명.png": {
      "topic": "사용된 주제명",
      "date": "YYYY-MM-DD",
      "blurred": true
    }
  },
  "AI생성이미지": { "주제명": ["thumbnail.png", "image-01.png", ...] }
}
```

- `date`: 글 생성 날짜 (오늘 날짜)
- `blurred`: 블러 처리 여부 (01/03/06/07 폴더면 `true`, 나머지는 `false`)
- 기존 항목(문자열 형식)은 수정하지 않는다. 새 항목만 객체 형식으로 추가한다.

## 이미지 소스 우선순위

```
0순위 — cases 폴더 사진 (현장사례 모드일 때만)
1순위 — 현장사진 (스마텍 직접 촬영, data/현장사진/)
2순위 — AI 생성 이미지 (HTML+CSS+Playwright)
```

> PPT 슬라이드(`블로그/output/user-images/`)는 텍스트 정보 참고 전용. 이미지로 사용 금지.
> `user-images/`에 `slide-XX.png` 패턴이 아닌 실제 현장·제품 사진이 있으면 `data/현장사진/` 적절한 폴더로 이동 후 1순위로 사용.

`블로그/data/cases/[케이스폴더]/` 의 photo*.jpg 를 우선 사용한다.

### 납품사진 (info.txt → `사진블러: 불필요`)
- **블러 처리 없이 그대로 사용**
- photo1.jpg → `field-1.png` 로 복사
- photo2.jpg → `field-2.png` 로 복사
- 배송 박스·포장 사진은 기밀 정보 없으므로 블러 불필요
- used-images.json 기록은 생략 (cases 폴더 사진은 재사용 추적 불필요)

### 현장사진 (info.txt → `사진블러: 필요`)
- 기존 블러 처리 4단계 의무 절차 그대로 적용
- 블러 후 `field-1.png` 로 저장

### 현장사례 썸네일
- cases 폴더 사진 중 가장 잘 나온 사진을 thumbnail로 사용
- 납품 포장 사진이 전부라면 그것을 thumbnail로 사용 (AI 생성 썸네일 불필요)

### ⚠️ 블러 처리 4단계 의무 검증 절차 (01, 03배경노출, 06, 07 폴더)

블러 처리는 아래 4단계를 모두 완료해야 "완료"로 처리한다.
어느 단계든 실패하면 해당 사진을 포기하고 다음 후보 사진 또는 AI 생성으로 대체한다.
**블러 미처리 원본 사용은 절대 불가.**

#### 1단계 — blur_preview.py로 격자 미리보기 생성 후 좌표 확인 (건너뛰기 금지)

```bash
python 블로그/blur_preview.py "data/현장사진/.../원본.jpg" "블로그/output/[주제]/images/preview_grid.png"
```

- Read 도구로 생성된 격자 이미지를 열어 시각적으로 확인한다.
- 격자 눈금(500px 간격)을 보고 펌프 본체의 x1·y1·x2·y2 좌표를 기록한다.
  기록 예: "펌프: 약 x=700~2600, y=1350~2750 (원본 4000×3000 기준)"
- **좌표를 추정만 하고 바로 실행하지 않는다. 격자로 직접 눈으로 확인한 값만 사용한다.**
- 펌프가 식별되지 않으면 이 사진은 사용하지 않는다.

#### 2단계 — blur-config.json 작성 후 blur_photo.py 실행

```json
{
  "pump_box": [x1, y1, x2, y2],
  "blur_radius": 55
}
```

```bash
python 블로그/blur_photo.py "원본경로" "블로그/output/[주제]/images/field-N.png"
```

- **blur_radius는 반드시 55 고정.** (기준: 2026-06-17 동결건조 글 작업에서 확정)
- **원본 파일(data/현장사진/...)을 입력으로 사용한다. 이미 처리된 field-N.png를 입력으로 쓰지 않는다.**
- Python 위치: `C:\Users\rokmc\AppData\Local\Programs\Python\Python312\python.exe`
- 실행 결과(터미널 출력)에 오류가 없는지 확인한다.

#### 3단계 — 블러 결과물 시각 확인 (Read 도구 필수, 건너뛰기 금지)
- Read 도구로 처리된 파일(field-N.png)을 반드시 직접 연다.
- 아래 두 가지를 모두 확인한다:
  - [ ] 펌프 본체 영역이 선명하게 보이는가?
  - [ ] 펌프 외 배경 영역이 흐릿하게 처리됐는가? (완전 불투명 아님, 흐릿하게 보여야 함)
- 둘 중 하나라도 NO이면 스크립트를 수정하고 2단계부터 재실행한다. (최대 3회)
- 3회 후에도 실패 시 이 사진을 포기하고 AI 생성 이미지로 대체한다.

#### 4단계 — 처리 완료 기록
```
블러 처리 완료:
- 원본: data/현장사진/07_기타/파일명.jpg
- 처리본: 블로그/output/[주제]/images/field-1.png ✅ 시각 확인 완료
- 펌프 좌표: (px1, py1, px2, py2) = (1400, 900, 2000, 1400)
- 배경 블러 radius: 55 (고정값) / 배관 blur radius: 해당 시 75 (55+20 자동 적용)
```

### 3단계 — 대표 이미지 (thumbnail.png)

현장사진 중 글 분위기에 가장 잘 맞는 사진을 선택해 thumbnail로 사용.
적합한 현장사진이 없을 경우에만 AI 생성으로 제작:
- 크기: 1080×1080 px
- 배경: `#1a1a2e` → `#16213e` 그라데이션
- 메인 텍스트: 글 제목 (흰색, 중앙 정렬)
- 보조 텍스트: 카테고리 또는 부제 (연한 회색)
- **브랜드 텍스트 삽입 금지**: SMARTECH, SMARTECH VACUUM, 전화번호, 웹사이트 모두 금지

#### 🔴 썸네일 여백 규칙 — 반드시 준수
- 전체 레이아웃은 `display:flex; flex-direction:column; justify-content:center; align-items:center` 로 중앙 정렬
- **위아래 패딩: 60px 이하** (기존 과도한 여백 금지)
- 텍스트 요소 간 간격(`gap` 또는 `margin`): 16px~24px 이내로 좁게
- 텍스트 블록 전체를 하나의 `<div>`로 묶어 세로 여백을 최소화
- HTML 예시 구조:
  ```html
  <body style="margin:0; width:1080px; height:1080px; display:flex; align-items:center; justify-content:center; background: linear-gradient(135deg,#1a1a2e,#16213e);">
    <div style="text-align:center; padding:60px; display:flex; flex-direction:column; gap:20px; align-items:center;">
      <span style="...카테고리 뱃지..."></span>
      <h1 style="...제목..."></h1>
      <p style="...부제..."></p>
    </div>
  </body>
  ```

### 4단계 — 본문 이미지 (AI 생성)

현장사진으로 채우지 못한 마커에 한해 AI 생성 이미지를 제작한다.

#### 유형 선택 기준
| 유형 | 선택 기준 |
|------|-----------|
| 비교 표 | 두 가지 이상을 나란히 비교 |
| 단계별 다이어그램 | 순서·절차·흐름 |
| 핵심 포인트 카드 | 3~5개 요점 정리 |
| 인용·강조 박스 | 중요한 수치·한 마디 강조 |

HTML+CSS로 마크업하고 Python+Playwright로 PNG 캡처한다.

```python
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content(html_content)
    page.set_viewport_size({"width": 너비, "height": 높이})
    page.screenshot(path="블로그/output/[주제]/images/파일명.png", full_page=False)
    browser.close()
```

### 5단계 — AI 생성 이미지 자체 검수 (최대 3회)

생성된 모든 이미지를 Read 도구로 열어 확인한다.

- [ ] **naver.md의 [IMAGE:설명] 캡션과 실제 이미지 내용이 일치하는가** (예: 캡션이 "내부 구조 비교"인데 실제로는 "조건 요약 카드"면 불일치 — 캡션을 바꾸거나 이미지를 다시 만든다)
- [ ] 펌프 영역이 선명하게 남아 있는가 (블러 처리 이미지)
- [ ] 본문 텍스트 폰트 크기가 최소 16px 이상인가 (소제목 20px 이상)
- [ ] 텍스트가 이미지 경계 안에 완전히 포함됐는가
- [ ] 텍스트와 배경 간 명도 대비가 충분한가 (어두운 배경 = 밝은 텍스트)
- [ ] 이미지 하단 빈 여백이 전체 높이의 20% 이하인가
- [ ] **본문 이미지에 전화번호·웹사이트·회사명이 없는가** (있으면 즉시 제거 후 재생성)

문제가 있으면 수정 후 재확인. 3회 후에도 문제 남으면 주석 달고 다음으로 넘어간다.

### 6단계 — 최종 파일명 통일 (사진1, 사진2, 사진3 …)

썸네일을 제외한 본문 이미지는 현장사진(field-N)이든 AI 생성(image-NN)이든 구분하지 않고,
**naver.md에 `[IMAGE: 설명]` 마커가 나오는 순서 그대로** `사진1.png`, `사진2.png`, `사진3.png` … 로 다시 이름 붙여 저장한다.

- 2~5단계에서 만든 field-N.png / image-NN.png는 작업용 임시 이름이다. 이 단계에서 최종적으로 `사진1.png`부터 순번을 다시 매긴다.
- 마커 개수와 최종 이미지 파일 개수가 반드시 일치해야 한다. 개수가 안 맞으면 이미지를 추가 제작하거나 마커를 정리해서 맞춘다 (개수 불일치 상태로 완료 처리 금지).

### 7단계 — naver.md는 마커를 그대로 둔다 / final.md에 실제 경로를 채운다

**🔴 naver.md의 `[IMAGE: 설명]` 마커는 실제 경로로 치환하지 않는다.** 네이버 블로그는 사람이 직접 에디터에 사진을 업로드하는 방식이라, 마커를 그대로 남겨둬야 어디에 사진을 넣을지 알 수 있다 (check_quality.py의 "네이버글" 검사도 `[IMAGE:` 마커 존재 여부로 판정한다 — 마커를 지우면 검수가 반려된다). 2026-07-24 이 규칙을 어겨서 3편 모두 검수 반려된 사고 있었음.

**final.md에는 반드시 실제 이미지 경로를 채워 넣는다.** writer 에이전트가 만든 final.md는 이미지가 비어있거나(H1 아래 thumbnail 누락) 아직 존재하지 않는 파일명(image-01.png 등)을 임시로 적어뒀을 수 있다. image-maker가 실제 파일을 사진1.png ~ 사진N.png로 확정한 뒤, 반드시 final.md를 열어:
1. H1 제목 바로 아래에 `![대표이미지 설명](./images/thumbnail.png)`가 있는지 확인하고 없으면 추가
2. 본문 각 H2 소제목 앞에 실제로 존재하는 사진N.png 파일만 순서대로 배치 (이미지 개수가 H2 개수보다 적으면 뒤쪽 H2 일부는 이미지 없이 비워도 된다 — 존재하지 않는 파일을 가리키는 태그를 남기지 않는 것이 최우선)
3. `grep -o "images/[^)]*" final.md` 결과와 `ls images/` 결과를 대조해서 100% 일치하는지 반드시 확인한다. final.md가 가리키는 파일이 하나라도 실제로 없으면 홈페이지에서 깨진 이미지로 보인다.
