# 블로그 SEO·GEO 작성 가이드

검토일: 2026-09-09. 검색엔진 공식 설명과 스마텍 내부 편집 기준을 구분한다. 특정 모델·발행량·글자수만으로 검색 순위나 AI 인용을 보장하지 않는다.

## 1. 공식 근거로 확인한 원칙

Google은 독창적 정보·명확한 출처·실제 전문성·오류 없는 설명을 강조한다. 선호하는 글자수는 없으며 내용 변화 없이 날짜만 바꾸는 방식은 권하지 않는다. [Google 콘텐츠 품질 안내](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)

제목은 내용을 정확히 설명하고 본문은 읽을 수 있게 구성한다. 관련 페이지 링크는 독자가 다음 정보를 찾을 수 있는 실제 경로로 제공한다. [Google SEO 기본 안내](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)

Google의 생성형 검색도 기본 SEO와 고유한 정보가 중요하다. 별도 문체·극단적인 문단 쪼개기·키워드 변형별 대량 글 작성은 필요하지 않다. Google은 llms.txt를 검색 노출·순위 평가에 사용하지 않는다고 설명한다. 다른 서비스의 활용 가능성과 Google 효과를 혼동하지 않는다. [Google 생성형 검색 안내](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)

구조화 데이터는 독자가 보는 내용과 일치해야 하며 검색 특수 표시를 보장하지 않는다. [Google 구조화 데이터 정책](https://developers.google.com/search/docs/appearance/structured-data/sd-policies)

Google FAQ 리치 결과는 2026-05-07부터 종료됐다. FAQ는 독자의 후속 질문에 답하기 위해 작성하며 특수 검색 결과 확보 수단으로 약속하지 않는다. [Google 변경 기록](https://developers.google.com/search/updates#may-2026)

네이버 서치어드바이저의 기본 안내는 검색엔진이 사이트 내용을 이해하도록 정리하는 목적을 설명한다. 웹사이트 안내를 네이버 블로그 내부 순위 공식으로 확대 해석하지 않는다. [네이버 검색엔진 최적화 목적](https://searchadvisor.naver.com/guide/seo-basic-intro)

## 2. 스마텍 내부 작성 기준

아래는 제작·검수를 위한 운영 기준이다. 검색엔진이 정한 점수 공식이 아니다.

- 한 글은 독자의 핵심 질문 하나에 답한다. 도입에서 답과 적용 범위를 먼저 제시한다.
- 제목은 질문과 내용을 정확히 나타낸다. 25~35자는 편집상 참고 범위이며 강제로 맞추거나 숫자·연도를 덧붙이지 않는다.
- 소제목은 의미 단위로 나누며 질문형이 자연스러울 때 사용한다. 비교는 목록·볼드 라벨로 표현하고 마크다운 표는 사용하지 않는다.
- 키워드는 실제 제품명·독자 표현을 자연스럽게 사용한다. 밀도 2~3%, 일정 반복 횟수 같은 목표는 사용하지 않는다.
- 현재 `check_quality.py`는 final.md 최소 2,000자, naver.md 최소 1,500자를 검사한다. 내부 기준이며 허구 사례·반복 문장으로 분량을 채우지 않는다. 검사가 의미 있는 원고를 길이만으로 반려하면 보고 후 기준 검토 전까지 발행을 보류한다.
- `meta.txt`의 접두사와 150~160자 설명은 기존 제작 형식이다. 설명은 해당 글의 실제 내용을 요약하며 검색 화면에 그대로 표시된다고 보장하지 않는다.
- 네이버와 홈페이지는 독자·형식에 맞게 구성을 조정한다. 사실과 적용 조건을 달리 쓰거나 다른 사례를 지어내지 않는다.

## 3. 기술적 신뢰 확보

- 핵심 수치·조합·기능·운전 조건은 research.md의 검증된 원문과 대조한다. 모델·가스·온도·압력·주파수·모드가 판단을 바꾸면 공개 문장에도 남긴다.
- 핵심 주장 근처에 제조사 공식 문서 링크를 넣는다. 자료를 그대로 옮기기보다 스마텍 독자가 확인할 기준을 설명한다.
- 실제 상담·납품·수리 기록이 있으면 익명화해 반영한다. 기록이 없으면 일반 이론·확인 항목을 설명하며 경력·고장 빈도·실측 성과를 만들어내지 않는다.
- 출처가 충돌하면 조건을 확인하고 미해결 사항은 사용자에게 확인한다. 내부 제품표라는 이유만으로 공식 원문과의 차이를 무시하지 않는다.
- 관련 공개 글·제품·서비스 링크는 실제 URL과 내용을 확인한다. 없는 글 ID나 임시 경로를 넣지 않는다.

## 4. 사진·FAQ·공개 화면

- 사진은 기존 이미지 지침에 따라 미사용 현장사진을 먼저 검토한다. 설명용 AI 이미지는 실제 납품·수리 사진처럼 소개하지 않는다.
- 이미지 개수·규격은 이미지 지침과 실제 배치에 맞춘다. 사진 수를 검색 순위 조건으로 제시하지 않는다.
- 캡션·대체 텍스트는 실제 보이는 부품과 설명을 일치시킨다. 네이버에 붙여넣을 때 작업용 이미지 마커와 검증 주석을 남기지 않는다.
- FAQ에는 본문에 필요한 후속 질문과 조건부 답변을 넣고, 파일·화면·구조화 데이터를 대조한다. 질문 수를 채우려고 같은 답을 반복하지 않는다.
- 홈페이지 본문 연락처 단락은 자동 표시 박스와 중복하지 않는다. 기술 근거·관련 페이지 링크는 허용한다.

## 5. 발행·보강·성과 확인

- 발행 주기는 2026-09-14부터 월·목 주 2편이다. 후보 5개 중 사용자 2개 선택 → 작성·검수 → 사진·원고 승인 → 지정 날짜 예약 또는 명시적 즉시발행 순서를 지킨다.
- 기존 글은 오류·적용 조건 누락·답변 부족·관련 링크 부족을 먼저 보강한다. URL을 유지하고 수정 이유·근거·검증 결과를 기록한다.
- 로컬 원고 수, 홈페이지 공개 수, 검색 색인 수를 구분한다. 발행 완료는 실제 글 ID·공개 화면으로 확인한다.
- Search Console 검색어별 노출·클릭과 문의 전환을 가능한 범위에서 비교한다. 데이터가 없으면 성과 개선을 확인했다고 말하지 않는다. 순위 변화에는 계절·검색 수요·경쟁 변화도 영향을 주므로 단순 전후 차이를 모델 효과로 단정하지 않는다.
- 과거 문서의 “50편이면 전문성 인정”, “고유정보 30%”, “하루 1~3개면 안전”, “서명 반복은 자동 감점” 같은 확인되지 않은 수치·알고리즘 단정은 운영 근거로 사용하지 않는다.
