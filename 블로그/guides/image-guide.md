# 이미지 제작 가이드

> image-maker 에이전트가 블로그용 이미지를 준비할 때 따르는 규격 및 스타일 기준입니다.

---

## 0. 이미지 소스 우선순위

주제·모델이 맞는 실제 사진을 우선하는 내부 제작 기준이다. 사진 종류만으로 검색 점수나 AI 인용을 보장하지 않는다. 세부 처리·사진 승인 절차는 `블로그/agents/image-maker.md`와 `블로그/CLAUDE.md`를 함께 따른다.

| 순위 | 소스 | 위치 |
|------|------|------|
| 1순위 | 현장사진 (스마텍 직접 촬영) | `C:\Users\rokmc\smartech\data\현장사진\` |
| 2순위 | 홈페이지 제품 참고 이미지 | `public/images/products/`, 글의 실제 모델·타입 확인 |
| 3순위 | 설명 도식·AI 생성 이미지 | 도식은 기존 HTML+CSS+Playwright, 사진·일러스트는 해당 도구 지침 |

현장사례는 `블로그/data/cases/`의 해당 사례 사진을 먼저 확인한다. 현장사진이 없으면 같은 타입인지 불명확한 사진으로 채우지 말고 대체 사유를 기록한다. 제품 참고·설명 이미지를 실제 현장사진처럼 소개하지 않는다.

> **PPT 슬라이드(`output/user-images/`)는 이미지로 사용 금지.**
> 슬라이드에는 시장분류·사용공정·제품명 등 텍스트 정보가 포함되어 있어 글쓰기 참고용으로만 활용한다.

### 현장사진 폴더별 사용 규칙

| 폴더 | 내용 | 처리 방식 |
|------|------|----------|
| 01_장비외관 | 펌프+주변 장비 외관 | **블러 처리 후 사용** |
| 02_납품출고 | 출고·배송 박스 | 납품 관련 글에만 사용 |
| 03_현장설치 | 설치·측정 클로즈업 | 고객사 배경 노출 시 블러 처리 |
| 04_수리정비 | 분해·수리 내부 사진 | 그대로 사용 |
| 05_알람고장 | 컨트롤러 화면 | 그대로 사용 |
| 06_비교도식 | 고객사 공장 배관 전경 | **블러 처리 후 사용** |
| 07_기타 | 펌프 스테이션 전경 | **블러 처리 후 사용** |

**블러 처리 기준:**
- 펌프 위치는 원본 격자 미리보기에서 직접 확인한다. 사진 모서리에 있다고 추측하지 않는다.
- 펌프 본체 영역: 선명하게 유지
- 블러가 필요한 사진은 image-maker의 현재 기준 **radius=55**를 설정한다. 배관 영역 처리를 지정하면 기존 스크립트가 radius+20을 적용한다. 블러 불필요 사진의 축소 전용 처리는 image-maker의 별도 규칙을 따른다.
- 처리된 파일은 캐시로 보관할 수 있지만 다른 글에 현장사진을 재사용하지 않는다. `output/used-images.json` 확인과 기록 담당자를 명확히 한다.
- 블러 여부와 무관하게 EXIF 방향·고객사 정보·1000px 폭 축소·4MB 이하 용량·최종 시각 확인을 수행한다. 사진 승인은 별도로 받는다.

## 1. 대표 이미지 (썸네일) 규격

| 항목 | 값 |
|------|-----|
| 크기 | 1080 × 1080 px (1:1 정사각형) |
| 배경 | 어두운 블루-퍼플 그라데이션 (`#1a1a2e` → `#16213e`) |
| 메인 텍스트 | 글 제목 — 큰 글씨, 흰색 (`#ffffff`) |
| 보조 텍스트 | 카테고리 또는 부제 — 작은 글씨, 연한 회색 (`#a0aec0`) |
| 텍스트 정렬 | 가로·세로 모두 중앙 정렬 |
| 폰트 | Pretendard (없으면 시스템 기본 한글 폰트) |
| 액센트 요소 | 우측 하단 또는 최상단에 작은 도형·코드 심볼·단순 아이콘 |
| 브랜드 표기 | image-maker 기준에 따라 회사명·전화번호·웹사이트 삽입 금지 |

## 2. 본문 삽입 이미지 종류

naver.md의 `[IMAGE: 설명]` 자리에 들어갈 이미지다. `[THUMBNAIL]`은 thumbnail.png 전용이며 본문 사진 개수에 포함하지 않는다. 설명을 읽고 내용에 맞는 유형을 선택한다. 원고의 공식 근거와 적용 조건을 그림 안에서도 유지하며 원고 링크를 삭제하지 않는다.

### 유형 1 — 비교 표
- **사용 시점**: 제품·방법·옵션을 나란히 비교할 때
- **구성**: 헤더 행 + 데이터 행, 열마다 항목 구분
- **예시 상황**: "A vs B", "방법 3가지 비교", "버전별 차이"

### 유형 2 — 단계별 다이어그램
- **사용 시점**: 절차나 순서를 보여줄 때
- **구성**: 번호 붙은 단계 블록을 화살표로 연결
- **예시 상황**: "설치 과정", "워크플로우", "데이터 흐름"

### 유형 3 — 핵심 포인트 카드
- **사용 시점**: 3~5개 요점을 한눈에 정리할 때
- **구성**: 카드 형태로 요점 나열, 각 카드에 아이콘 또는 번호
- **예시 상황**: "핵심기능 5가지", "장점 정리", "체크리스트"

### 유형 4 — 인용·강조 박스
- **사용 시점**: 중요한 한 마디나 수치를 강조할 때
- **구성**: 큰 따옴표 또는 굵은 텍스트 + 출처 또는 설명 한 줄
- **예시 상황**: "통계 수치 강조", "핵심 인용문", "경고·주의사항"

## 3. 공통 디자인 규칙

- **배경 톤**: AI·테크 분위기에 어울리게 어두운 계열 유지
- **텍스트 분량**: 최대한 짧게. 이미지는 보조 수단이며 본문을 대체하지 않음
- **코드 스타일 활용 가능**: 모노스페이스 폰트·어두운 배경의 코드 블록을 디자인 요소로 사용
- **여백**: 충분한 패딩으로 답답하지 않게
- **검수 기준**: 최신 image-maker 지침의 실제 크기·잘림·여백 기준을 적용한다. 이미지 속 중요한 정보는 본문 텍스트에도 제공한다. 이미지로 만든 비교표는 본문 마크다운 표 금지와 별개지만 출처·조건·가독성 검사는 동일하다.

## 4. 제작 방법 (공통)

```
1. HTML+CSS로 이미지 레이아웃 작성
2. Python + Playwright로 브라우저에서 렌더링
3. screenshot() 으로 PNG 캡처
4. output/[주제]/images/ 디렉터리에 저장
```

파일 네이밍 규칙:
- 대표 이미지: `thumbnail.png`
- 본문 삽입 이미지: 작업 중 `image-01.png` 등을 쓸 수 있으나 최종은 `사진1.png`, `사진2.png`, ... (naver.md 본문 마커 순서 기준).
- naver.md는 편집용 마커를 보존하고 final.md에는 실제 경로를 넣는다. 네이버에 실제 게시할 때 마커를 사진으로 교체하며 작업용 주석이 공개되지 않게 확인한다.
